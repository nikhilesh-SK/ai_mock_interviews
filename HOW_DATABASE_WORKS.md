# How the Database Works

The application uses **Google Firebase Firestore**, a NoSQL cloud database, to store and sync data.

## Database Schema

The database consists of three main collections: `users`, `interviews`, and `feedback`.

### 1. Users Collection (`users`)
Stores user profile information.
- **Document ID**: The Firebase Auth `uid`.
- **Fields**:
  - `name`: User's display name.
  - `email`: User's email address.
  - `createdAt`: Timestamp of account creation (ISO string).
  - `profileURL`: (Optional) URL to user's profile image.

### 2. Interviews Collection (`interviews`)
Stores details of generated mock interviews.
- **Document ID**: Auto-generated by Firestore.
- **Fields**:
  - `userId`: The `uid` of the user who created the interview (Foreign Key equivalent).
  - `role`: Job role (e.g., "Frontend Developer").
  - `type`: Interview type (e.g., "Technical", "Behavioral").
  - `level`: Experience level (e.g., "Junior", "Mid-level").
  - `techstack`: Array of strings listing relevant technologies (e.g., `["React", "Node.js"]`).
  - `questions`: Array of strings containing the AI-generated interview questions.
  - `finalized`: Boolean indicating if the interview generation is complete (usually `true`).
  - `coverImage`: URL string for a random cover image assigned to the interview.
  - `createdAt`: Timestamp of interview creation (ISO string).

### 3. Feedback Collection (`feedback`)
Stores AI-generated feedback and scores for completed interviews.
- **Document ID**: Auto-generated by Firestore.
- **Fields**:
  - `interviewId`: The ID of the related interview document.
  - `userId`: The `uid` of the user who took the interview.
  - `totalScore`: Number representing the overall performance score.
  - `categoryScores`: Object containing scores for specific categories (e.g., Communication, Technical).
  - `strengths`: Array of strings listing candidate's strengths.
  - `areasForImprovement`: Array of strings listing areas to improve.
  - `finalAssessment`: String containing a summary paragraph of the performance.
  - `createdAt`: Timestamp of feedback generation (ISO string).

## Data Relationships

- **User -> Interviews**: One-to-Many. A user can create multiple interviews. Queries filter by `userId`.
- **Interview -> Feedback**: One-to-One. Each interview session typically generates one feedback report (though re-takes could theoretically create more).
